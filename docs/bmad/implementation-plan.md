### 接入与验证

1. 在百炼北京地域创建试点和生产业务空间。试点使用授权合成样例，密钥存服务端密钥管理。控制台逐个核对快照可用性、实际 RPM、TPM、计费档位和数据处理设置。
2. 后端使用 Node.js `fetch` 调用 `POST https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1/chat/completions`。后台入口用非流式响应，关闭思考、搜索和工具调用。每个快照使用允许名单、每任务输出上限及端到端超时。
3. 文本和视觉先统一使用 `json_object`。指令明确要求返回 JSON，响应必须通过 Ajv 校验及业务验证。视觉输入在消息的 `content` 数组中用 `type: "image_url"` 传入脱敏裁片的 Base64 Data URI，并附独立文本项。整份私有原卷与 OSS 签名链接留在自有系统。
4. 对四个快照各执行一次最小样例调用，再跑授权样卷对照组。记录模型、版本、响应时间、HTTP 状态、结束原因、用量及供应商请求 ID。验证解析失败、内容截断、限流和未知计费状态。

文本接入样例。先在安全的终端环境设置 `BAILIAN_WORKSPACE_ID` 和 `DASHSCOPE_API_KEY`，避免将真实密钥写入历史记录或工单。

```bash
curl --fail-with-body --silent --show-error --max-time 30 \
  "https://${BAILIAN_WORKSPACE_ID:?}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1/chat/completions" \
  -H "Authorization: Bearer ${DASHSCOPE_API_KEY:?}" \
  -H 'Content-Type: application/json' \
  --data '{
    "model": "qwen-flash-2025-07-28",
    "stream": false,
    "enable_thinking": false,
    "response_format": {"type":"json_object"},
    "max_tokens": 128,
    "messages": [
      {"role":"system","content":"返回 JSON 对象，包含 answer 和 steps 两个字段。"},
      {"role":"user","content":"解方程 2x + 3 = 7。"}
    ]
  }'
```

### 模型任务合约

| 任务 | 输入与最小输出 | 升级或拒收条件 |
|---|---|---|
| `recognize_page` | 页 ID、旋转后坐标系、图像及文本提示 → `blocks[{blockId,kind,bbox,text,latex}]`、可见页码、缺损标记 | 检查坐标在 [0,1]、题号连续性、选项及图表关联。未通过时仅重读相关裁片一次，仍冲突则待人工。模型产生的 blockId 仅限本次结果，持久 ID 由服务端生成。 |
| `solve_question` | 确认题版本、选项、共享材料及授权裁片 → `status,answer,steps,rubric,concepts,sourceRefs` | 常规文本走 Flash。复杂计算、开放论证或规则不一致走文本 Plus，视觉依赖走 VL Plus。证据不足返回待核验。考点先修关系需有效证据。 |
| `grade_subjective` | 已提交作答、锁定的评分要点 → `hits,misses,evidenceSpans,status` | 程序检查引文确实出现在作答中。图像或缺少可用评分标准时转自评或复核，已通过专项验收的图像分层可单独开放。 |
| `generate_prediction` | 同科证据 ID、题型和考点配额、已有题摘要 → `questions[{type,stem,answer,rubric,evidenceRefs,rationale}]` | 校验引用集合、题型、重复、答案完整性与可解性。材料不足或未通过检查时保留原当前版本，记录失败原因。 |

统一结果信封包含 `schemaVersion` 和 `status`。源位置、题目身份、租户及版本均从服务端上下文验证。解析、解题和预测各自保存提示词版本，缓存只在同租户与同输入版本内复用。

## 4. 先冻结的运行契约

| 场景 | 具体规则 |
|---|---|
| 上传 | `POST /uploads` 返回 uploadId、受限凭证和过期时间。完成接口按同一 uploadId 幂等返回 jobId。文件名与客户端哈希仅作提示，服务端验证对象版本及内容。 |
| 草稿 | 保存提交 `attemptId,baseRevision,changes`。锁内只接受当前修订，返回下一修订。交卷附最终草稿时沿用相同规则；超过截止时间只结算服务端已确认修订。 |
| 队列 | 消息只带 jobId。逻辑键按租户、任务类型、资源 ID、输入版本和路由版本去重。业务状态为 `queued → running → succeeded / failed / superseded`，可重试错误先进入 `retry_wait`。超过截止或失败次数后可人工重试。 |
| 模型发布 | Worker 在短事务中抢任务并预留额度，释放数据库连接后推理。结束后按租约与输入版本写入。供应商超时先记未知计费，自动重试受尝试上限和预算约束。 |
| 预测 | 按当前证据版本集合生成摘要。生成开始和发布时均校验摘要。只在发布事务里移动当前卷指针，历史会话锁定原预测版本。 |

## 5. 试点验收与降级

- **配额** 按真实账号、快照和场景分别计算。安全吞吐取 `min(RPM, TPM / 平均每次计费 Token) × 0.7`，再结合延迟反推 worker 并发上限。若官方目录与实际账号存在差异，以真实请求压测和控制台为准。B01 记录支持的每分钟卷数，再配置新上传准入和排队上限。模型 429 后按 `Retry-After`（若有）与抖动退避，禁止自动切到高价模型消化流量。
- **验收** 1,000 人并发草稿保存，10 秒内集中提交 1,000 份，同时灌入导卷负载。有效提交成功率 ≥99.9%，交卷 P95 ≤1 s。重复消息、重试及版本竞争情况下，重复结算与过期覆盖均为 0。
- **评测** 使用经过授权且按原卷隔离的盲测集。识别看题目边界、选项、关键公式和坐标；解答看正确率、关键步骤和评分点；预测看证据、可解性和答案。详细阈值见[生产架构](architecture.md)。上线报告同时列出人工校对耗时、拒答率、升级率、单卷实付费用及未开放的分层。
- **故障演练** 切断模型 15 分钟、模拟超时已计费、重复交卷、模拟数据库休眠。验证旧题仍可练习，草稿能重放，待处理任务可恢复，告警不记录试卷内容。
- **费用** 每次调用先按最坏输入、输出与价格预留，回收实际差额。日预算 70% 告警、85% 暂停新预测、100% 暂停新模型工作。交卷、错题、历史仍可用。试点可先限每人 5 套/天和各 1 个导卷、预测并发，依据实际质量和成本调整。

**首个工程迭代**并行完成 B01、B02，接着打通 B03～B06 的最小流程。首个演示使用一份可直提的 PDF 和一组跨页照片，完成上传、识别、人工确认及开练。随后交付 B07～B09 的完整复习闭环，最后接入预测并做考季验收。

适配范围为大学所有采用纸笔考试的课程。数据结构、线性代数和大学物理是当前合成回归批次。每科发布验收须有 50 份真实测试卷和 5 份独立评测卷。卷数是入库门槛，架构中的题目级质量门槛同时适用。[样本清单与校验](../../app/eval/README.md)
