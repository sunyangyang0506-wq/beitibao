# 个人题干修订与练习版本交付

本次包含实现、合成数据测试与隔离 CI 配置。发布范围仅为独立分支和草稿 PR，不合并、部署、迁移生产数据或调用付费模型。下文的本地验证记录不代表远端 CI 已通过。

## 行为与验收

依据 product-rules AI-05、PRG-02：实质题干修改产生账号内的新输入版本。旧题面、旧答案、自评和已结算成绩保留；当前覆盖不再按相同题 ID 误计。首尾空白及 CRLF/LF 编码差异不产生新版本，内部空白和其他文本差异保守视为内容变化，不猜测语义等价。

- 修订事务先归档题面、参考答案、模型结果和个人自评/笔记，再清空新版旧判分依据和模型租约，撤销旧等价关系。模型按新题面重新排队，仅在现有模型授权与开关允许时进行。
- 新版不使用原卷模型缓存，不参与校内共享；解题提示明确以用户修订条件为准。预测输入摘要随当前题面变化，旧预测结果保持历史身份。
- 已提交练习再次开练，若题面/图表/题型发生变化，先归档旧会话再创建新会话。会话 ID 与草稿修订号均变化，旧保存请求和旧定时事件不写入新会话。
- 未提交练习不被偷偷改题。原卷面继续作答，提交时读取该旧输入版本已经存在的答案；结果标注已有新版，不计新版覆盖。
- 已完成答案快照不可被后续答案替换。未完成解析仍允许从完全匹配的输入版本补齐，包括已归档答卷中未修改题的迟到解析。只更新归档的 graded/solution_snapshots 两列，题面、作答、时间不更新。
- 进度汇总当前与历史会话中仍匹配当前输入版本的有效作答；未改题的已练覆盖保留。旧版错题保存在历史，新版最新有效答对不会重新出现在当前待重练列表。
- 前端可选择历史作答。新版闭卷期间历史答案、错题答案和直接重练均受服务端保护。GET 读取期间发生重开时重新检查状态并拒绝旧答案响应。
- 自评和题干编辑携带输入版本，过时窗口不能把旧版自评或编辑写进新版。浏览器草稿与冲突合并要求明确匹配会话 ID。

## 数据与接口

迁移 040 新增 paper_questions.input_revision、practice_attempts.attempt_id、question_recall.assessed_revision、question_revision_history、practice_history、submitted_practice_history 及保守文本归一函数。旧 stem_correction 在升级时归档原始依据，再转为个人当前版本，撤销共享，保留旧答卷。升级期间显式处理表所有者的 FORCE RLS，并在结束恢复所有相关策略。

- GET /papers/:paperId/practice/history：历史会话索引。
- GET /papers/:paperId/practice/history/:historyId：只读历史结果，闭卷时返回 409。
- stem-correction 和 assessment 接收 inputRevision。兼容旧客户端首次版本默认 1；更新后旧客户端必须重新加载。
- API、独立定时队列、本地 Worker 权限脚本一起更新。题目历史仅可追加/读取/随授权删除；作答历史仅补齐缺失依据与判分，不授予全文 UPDATE。

## 锁顺序与安全边界

修订：课程材料锁 → 试卷锁 → 当前题/会话 → 当前结果 → 作答历史。

重开：试卷锁 → 会话 → 当前结果 → 作答历史 → 替换当前会话。

错题读取：按 UUID 有序共享锁定相关试卷 → 当前结果 → 作答历史。历史详情/结果呈现先共享锁卷并复核闭卷状态。

删除：课程材料锁 → 发现完整关联集合 → 按 UUID 有序锁定全部卷 → 复查课程与关联集合 → 删除从属记录。集合变化时返回 409，不能一边持有高 ID 卷锁一边追加低 ID 卷锁。历史记录纳入授权删除路径。

这些规则通过顺序 SQL 与可控交错测试验证，不等于原生 PostgreSQL 并发、死锁或负载验收。

## 可重复检查

- app：npm run lint、npm run build。
- app：npm test 通过 scripts/test-local.sh 在临时 PostgreSQL 中创建最小权限 API、Worker 角色。新增 question-versions.test.mjs 覆盖版本链路；question-version-upgrade.test.mjs 使用单独空库与 NOSUPERUSER NOBYPASSRLS 所有者跑 039→040。不得把升级测试 URL 指向应用库。
- pc-prototype：npm run test:unit、npm run build:connected、npm run build、npm run test:sites。

本环境实际运行：PGlite 的 40 个迁移、受限 API/队列/本地 Worker 合成场景、非超级用户所有者升级场景、定向纯函数和模型替身测试、前端构建及单元测试。原生 PostgreSQL 无法启动 socket，因此完整 npm test/coverage、真实并发、性能、恢复/回滚仍须在可用 PG16 环境复验。浏览器交互与真实模型质量也不能由构建或替身测试代替。

## 上线前风险

先在预发库验证升级、租户隔离和新旧权限，再协调 API 与 Worker 版本切换。归档增长及历史关联查询需真实数据量性能评估；历史列表当前未分页。模型对修订题面的真实质量、独立浏览器多窗口/断网流程、标准全量测试和生产回滚方案尚未完成验收。生产迁移、费用及正式发布仍需另行批准。
