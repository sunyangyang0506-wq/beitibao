## 实现规则

- 先读当前任务的需求、验收条件和相关代码。优先复用现有组件、接口和测试工具，保持改动围绕用户成果。
- 用户界面覆盖适用的加载、空态、失败和恢复路径。变更交互时，在真实浏览器核对目标设备、键盘操作和实际内容。
- 改动接口、权限或存储时，检查既有调用方与历史数据。写入流程按需验证重复提交、并发、部分失败和重试。
- 数据与 AI 功能按需求表执行固定样本检查。记录数据、索引、模型和提示词版本中适用的部分。
- 影响范围或用户行为的实质性取舍，记录到当前需求文件。常规实现细节按现有约定推进。
- 生产操作遵守当前任务授权和仓库的发布流程。上线前确认目标环境、观测指标和回滚步骤。

## 完成标准

- 从正常入口验证需求列出的成功和失败场景。发现可复现的问题，修复后重跑相关检查。
- 提交结果包括改动摘要、实际执行的检查与结果、相关证据、尚未验证的项目及原因。界面改动附关键状态截图，性能和评测改动附基线与对比条件。
- 发布前的通过标准以当前功能需求和发布清单为准。
