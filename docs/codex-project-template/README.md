# Codex 软件项目模板

适合新项目，也适合已有仓库。模板里的方括号是待填写项。先选一条最重要的用户流程试跑，例如「上传文档 → 索引完成 → 提问 → 打开引用原文」。

## 10 分钟开工

1. 把 `AGENTS.md` 和 `docs/` 下的文件复制到项目仓库。已有同名文件时，合并适用内容并保留原有规则。
2. 在 Codex 中打开该仓库。在 `AGENTS.md` 填写启动和验证命令，在 `docs/feature-brief.md` 写下目标用户、流程和验收条件。
3. 打开「产品与验收」对话，粘贴 `docs/codex-chats.md` 对应提示词。确认第一条流程后，再开「设计与交互」和「实现」对话。
4. 按 `docs/release-checklist.md` 记录证据。先验证一条流程，再扩大范围。项目无 AI 功能时，把模型评测项标成不适用。

## 文件怎么用

| 文件 | 记录什么 |
|---|---|
| `AGENTS.md` | 长期适用的仓库规则、命令和完成标准 |
| `docs/feature-brief.md` | 单个功能的需求、验收条件、决策和交接记录 |
| `docs/codex-chats.md` | 七类对话的开场提示词与输入、输出 |
| `docs/release-checklist.md` | 一次发布的检查、证据和回滚条件 |

同时开发多个功能时，为每个功能复制一份需求表。发布清单也可以按版本复制。新对话第一条消息附上对应需求文件路径、分支或提交、运行入口和已知限制。两条实现对话同时改代码时，使用独立分支或工作树，合并后重跑共用流程。

最小用法是三条对话：「产品与设计」「实现与验证」「独立验收」。模型、数据或发布本身有较大风险时，再为这些工作单开对话。
