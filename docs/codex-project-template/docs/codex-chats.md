# Codex 对话与开场提示词

复制对应代码块到 Codex。把方括号替换为当前功能的实际信息。小项目可以合并相邻对话，独立验收建议用新对话。

## 1. 产品与验收

输入：用户问题、现有产品入口、业务约束。交付：确认过的功能需求表。

```text
阅读 AGENTS.md 和 [需求文件]。本轮要帮助 [用户] 完成 [任务]。先检查现有入口和可用资料，给出当前行为和主要问题。把工作收敛到一条可交付流程，写出起点、成功结果、关键失败场景和范围。在需求文件逐项填写可观察的验收条件、证据和待决定的取舍。已有功能先测基线，缺少证据的假设请标出。此轮交付需求与验收草案。
```

## 2. 设计与交互

输入：需求表、品牌规范、参考图、真实内容样例。交付：关键页面、状态与设计说明。

```text
根据 [需求文件]、[设计规范] 和 [参考图] 设计核心流程。先梳理信息层级、操作顺序和反馈，再给出可审阅的界面稿或原型。用真实长度的内容覆盖桌面和移动端，呈现加载、空态、失败、重试和成功状态中适用的部分。说明键盘焦点、错误提示、长文本和窄屏处理。附关键截图，把确定的组件、状态和交互规则写回需求文件供实现使用。
```

## 3. 功能实现

输入：确认后的需求与设计、代码分支。交付：可运行改动和验证结果。

```text
在 [分支] 实现 [需求文件] 中的核心流程，按 [设计稿] 落地。先核对现有组件、接口、数据和测试入口，记录相关基线。做能从真实入口使用的完整功能，验证旧调用方、历史数据、权限和异常路径中受影响的部分。运行 AGENTS.md 中适用的检查，真实操作页面并截图。修复可复现的问题后重测，交付运行入口、改动摘要、验证结果和剩余限制。
```

## 4. 数据质量与时效性

输入：数据源、目标表或索引、权限规则、新鲜度目标。交付：数据对账与更新延迟结果。

```text
按 [需求文件] 检查 [数据源] 到 [用户可见结果] 的链路。在测试环境使用脱敏样本，记录数据来源、版本和采样范围。检查字段、缺失、重复、权限与对账结果。实测新增、更新、删除以及失败重跑，测量从源数据变更到用户可见的时间。报告具体差异、受影响场景、证据和建议修复顺序。对本轮授权的修复，完成后用同样样本复测。
```

## 5. AI 功能评测（适用时）

输入：基线版本、候选版本、固定用例和评分规则。交付：可复跑评测与失败归因。

```text
对 [AI 功能] 评估 [基线版本] 和 [候选版本]。使用 [固定评测集]，记录模型、提示词、检索配置、数据和索引版本。样本覆盖常见问题、边界、无答案和权限风险。按预先约定的标准比较准确性、引用、恰当拒答、延迟和成本。把检索命中与最终答案分开检查，用人工抽查校准自动评分。结果附样本量、退化用例、通过条件和复跑命令。缺少可信标签时，明确标注相应结果待验证。
```

## 6. 独立验收

输入：需求、候选提交、运行入口、测试账号。交付：可复现的问题与发布判断。

```text
以独立验收者的视角审查 [提交或 PR]。以 [需求文件] 和 [发布清单] 为准，从 [运行入口] 走成功、失败和恢复场景，核对设计、权限、旧数据与测试覆盖。先完成验收记录，再交给实现对话修复。每个问题写明影响、复现步骤、预期、实际表现和证据，给出是否阻塞发布的理由。未执行的检查写明原因和补验方法。
```

## 7. 发布与上线观察

输入：已验收提交、发布流程、目标环境、指标和回滚阈值。交付：发布记录、观测结果和处置状态。

```text
按 [发布说明] 与 [发布清单] 核对 [候选版本]。确认目标环境、检查结果、迁移步骤、观测窗口、告警阈值、回滚方式与负责人。执行本轮已授权的操作。发布后按约定窗口检查核心流程、错误率、延迟和数据新鲜度，记录版本、时间和指标。如果触发回滚条件，按既定授权和预案处置，并验证恢复。交付发布结果、待验证项和后续跟进。
```
