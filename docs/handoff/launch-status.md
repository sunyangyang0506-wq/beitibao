## 版本验收方式

构建发布镜像必须提供 `BEITIBAO_BUILD_REVISION`（完整 40 位 Git SHA），镜像生成 `release-revision.json` 并写入 OCI revision 标签。`/healthz` 返回镜像内清单的提交号，响应禁用缓存；开发环境缺少清单时返回 `revision: null`。格式损坏的清单使启动失败。

`verify-release.mjs` 要求 `BEITIBAO_ACCEPTANCE_REVISION`，在任何登录、上传等操作前拒绝缺失或不匹配的线上版本。成功结果明确标注 `synthetic-infrastructure-smoke`：它验证合成材料的基础设施链路，不代表真实识别、答案准确率、全量范围或正式发布通过。[操作说明](../../app/infra/beijing/README.md)

## 恢复任务时

1. 读取本文件，取得当前主分支和关联 PR 的实际状态，不沿用旧正文里的“未合并”。
2. 比较已检出的代码、当前检查对应的提交和线上版本；不确定项保留“待核实”。
3. 处理最高优先级且可执行的阻塞项，修复后复测，保存证据及失败原因。
4. 仅在全部既定放行条件满足后更新上线结论；最终汇报区分已合并、已部署、已验收和仍受阻的事项。
